Bases de datos asíncronas

1. Objetivo de la sesión

Al finalizar esta sesión, el aprendiz será capaz de explicar qué resuelve la programación asíncrona en un servidor web, convertir la capa de datos y los endpoints de BiblioAPI a SQLAlchemy asíncrono con AsyncSession, y decidir con criterio cuándo async aporta rendimiento y cuándo solo añade complejidad.

2. Qué resuelve async y qué no

Un endpoint que consulta la base pasa la mayor parte de su tiempo esperando: la CPU está ociosa mientras llega la respuesta del motor. En el modelo síncrono, ese hilo queda bloqueado. Con async, la función cede el control en cada await y el bucle de eventos atiende otras peticiones mientras tanto.

Concepto

Descripción

Bucle de eventos

Único hilo que ejecuta las corrutinas. Mientras una espera, atiende otra. Si algo lo bloquea, se detiene todo.

async def

Declara una corrutina. No se ejecuta al llamarla: hay que esperarla con await.

await

Punto de cesión. Marca dónde la función suspende su ejecución y devuelve el control al bucle.

Operación de E/S

Consultas a la base, llamadas HTTP, lectura de archivos. Son las que se benefician de async.

Operación de CPU

Cálculo, cifrado, inferencia de un modelo. No se benefician: ocupan el procesador y bloquean el bucle.

Driver asíncrono

aiosqlite para SQLite, asyncpg para PostgreSQL. Sin driver asíncrono, async no aporta nada.

Idea clave

async no acelera una petición aislada: la consulta tarda lo mismo. Lo que mejora es cuántas peticiones concurrentes soporta el servidor con los mismos recursos. Con un solo usuario en clase, la diferencia es imperceptible; con doscientos, es la diferencia entre responder y encolarse.

Cuándo NO conviene async

Cuando la operación es de CPU: una inferencia de scikit-learn dentro de un async def bloquea el bucle de eventos y degrada toda la aplicación, no solo esa petición.

Cuando se llama a una librería síncrona sin equivalente asíncrono: un cliente de pago que usa requests dentro de un async def bloquea igual que si no hubiera async.

Cuando el proyecto es pequeño y el equipo no domina el modelo: FastAPI ejecuta los def normales en un pool de hilos y el resultado es correcto. Un async def mal escrito es peor que un def bien escrito.

Cuando la base de datos no tiene driver asíncrono disponible o el ORM no lo soporta para lo que se necesita.

Equivalencia con Django REST Framework

DRF nació sobre WSGI, síncrono por construcción; el soporte asíncrono de Django llegó después y el ORM sigue exigiendo sync_to_async para gran parte de las operaciones. FastAPI corre sobre ASGI desde el primer día y admite indistintamente def y async def en el mismo proyecto. La regla práctica: si la función hace await, debe ser async def; si usa una librería síncrona, se deja como def y FastAPI la ejecuta en un hilo aparte.

from sqlalchemy import func, select

from sqlalchemy.exc import IntegrityError

from sqlalchemy.ext.asyncio import AsyncSession

from app.errores import ConflictoDeNegocio, RecursoNoEncontrado

from app.models.biblioteca import Autor, Categoria, Libro, Prestamo

async def listar(

 sesion: AsyncSession,

 categoria: str | None = None,

 anio_min: int | None = None,

 buscar: str | None = None,

 solo_disponibles: bool = False,

 limite: int = 10,

 desplazamiento: int = 0,

) -> list[Libro]:

 consulta = select(Libro)

 if categoria is not None:

 consulta = consulta.join(Libro.categoria).where(Categoria.nombre == categoria)

 if anio_min is not None:

 consulta = consulta.where(Libro.anio_publicacion >= anio_min)

 if buscar is not None:

 consulta = consulta.where(Libro.titulo.ilike(f"%{buscar}%"))

 if solo_disponibles:

 consulta = consulta.where(Libro.ejemplares_disponibles > 0)

 consulta = consulta.order_by(Libro.titulo).offset(desplazamiento).limit(limite)

 resultado = await sesion.scalars(consulta)

 return list(resultado.unique())

async def obtener_o_fallar(sesion: AsyncSession, libro_id: int) -> Libro:

 libro = await sesion.get(Libro, libro_id)

 if libro is None:

 raise RecursoNoEncontrado("un libro", libro_id)

 return libro

async def _validar_relaciones(

 sesion: AsyncSession, autor_id: int, categoria_id: int

) -> None:

 if await sesion.get(Autor, autor_id) is None:

 raise RecursoNoEncontrado("un autor", autor_id)

 if await sesion.get(Categoria, categoria_id) is None:

 raise RecursoNoEncontrado("una categoría", categoria_id)

async def crear(sesion: AsyncSession, datos: dict) -> Libro:

 await _validar_relaciones(sesion, datos["autor_id"], datos["categoria_id"])

 libro = Libro(**datos, ejemplares_disponibles=datos["ejemplares_totales"])

 sesion.add(libro)

 try:

 await sesion.commit()

 except IntegrityError:

 await sesion.rollback()

 raise ConflictoDeNegocio(

 f"Ya existe un libro registrado con el ISBN {datos['isbn']}."

 )

 # refresh recarga también las relaciones eager, necesarias para responder

 await sesion.refresh(libro, attribute_names=["autor", "categoria"])

 return libro

async def actualizar(sesion: AsyncSession, libro_id: int, cambios: dict) -> Libro:

 libro = await obtener_o_fallar(sesion, libro_id)

 if "autor_id" in cambios or "categoria_id" in cambios:

 await _validar_relaciones(

 sesion,

 cambios.get("autor_id", libro.autor_id),

 cambios.get("categoria_id", libro.categoria_id),

 )

 if "ejemplares_totales" in cambios:

 prestados = libro.ejemplares_totales - libro.ejemplares_disponibles

 libro.ejemplares_disponibles = max(cambios["ejemplares_totales"] - prestados, 0)

 for campo, valor in cambios.items():

 setattr(libro, campo, valor)

 await sesion.commit()

 await sesion.refresh(libro, attribute_names=["autor", "categoria"])

 return libro

async def eliminar(sesion: AsyncSession, libro_id: int) -> None:

 libro = await obtener_o_fallar(sesion, libro_id)

 activos = await sesion.scalar(

 select(func.count())

 .select_from(Prestamo)

 .where(

 Prestamo.libro_id == libro_id,

 Prestamo.fecha_devolucion_real.is_(None),

 )

 )

 if activos:

 raise ConflictoDeNegocio(

 f"El libro tiene {activos} préstamo(s) activo(s); no puede eliminarse."

 )

 await sesion.delete(libro)

 await sesion.commit()

from datetime import date, timedelta

from sqlalchemy import func, select

from sqlalchemy.exc import IntegrityError

from sqlalchemy.ext.asyncio import AsyncSession

from app.crud import libros as crud_libros

from app.errores import (

 ConflictoDeNegocio,

 LimiteDePrestamosSuperado,

 PrestamoYaDevuelto,

 RecursoNoEncontrado,

 SinEjemplaresDisponibles,

 SocioInactivo,

)

from app.models.biblioteca import Prestamo, Socio

LIMITE_PRESTAMOS_ACTIVOS = 3

async def registrar(

 sesion: AsyncSession, libro_id: int, socio_id: int, dias_prestamo: int

) -> Prestamo:

 socio = await sesion.get(Socio, socio_id)

 if socio is None:

 raise RecursoNoEncontrado("un socio", socio_id)

 if not socio.activo:

 raise SocioInactivo(socio_id)

 activos = await sesion.scalar(

 select(func.count())

 .select_from(Prestamo)

 .where(

 Prestamo.socio_id == socio_id,

 Prestamo.fecha_devolucion_real.is_(None),

 )

 )

 if activos >= LIMITE_PRESTAMOS_ACTIVOS:

 raise LimiteDePrestamosSuperado(socio_id, LIMITE_PRESTAMOS_ACTIVOS)

 libro = await crud_libros.obtener_o_fallar(sesion, libro_id)

 if libro.ejemplares_disponibles <= 0:

 raise SinEjemplaresDisponibles(libro_id)

 hoy = date.today()

 prestamo = Prestamo(

 libro_id=libro_id,

 socio_id=socio_id,

 fecha_prestamo=hoy,

 fecha_devolucion_esperada=hoy + timedelta(days=dias_prestamo),

 fecha_devolucion_real=None,

 )

 libro.ejemplares_disponibles -= 1

 sesion.add(prestamo)

 try:

 await sesion.commit()

 except IntegrityError:

 # Lo impide uq_prestamo_unico: mismo socio, mismo libro, mismo día

 await sesion.rollback()

 raise ConflictoDeNegocio(

 "El socio ya tiene registrado hoy un préstamo de ese libro."

 )

 except Exception:

 await sesion.rollback()

 raise

 await sesion.refresh(prestamo)

 return prestamo

async def registrar_devolucion(

 sesion: AsyncSession, prestamo_id: int

) -> Prestamo:

 prestamo = await sesion.get(Prestamo, prestamo_id)

 if prestamo is None:

 raise RecursoNoEncontrado("un préstamo", prestamo_id)

 if prestamo.fecha_devolucion_real is not None:

 raise PrestamoYaDevuelto(prestamo_id)

 prestamo.fecha_devolucion_real = date.today()

 # prestamo.libro está cargado porque la relación es eager

 prestamo.libro.ejemplares_disponibles += 1

 await sesion.commit()

 await sesion.refresh(prestamo)

 return prestamo

Punto de atención

verificar_contrasena no lleva await, y es deliberado: Argon2 es una operación de CPU, no de E/S. Con un volumen alto de inicios de sesión conviene sacarla del bucle de eventos con run_in_threadpool; con el volumen de una biblioteca, dejarla así es razonable y es la clase de decisión que hay que saber justificar.

4. Ejemplo detallado: explicación línea por línea

N°

Elemento

Explicación

1

sqlite+aiosqlite:///…

El driver forma parte de la URL. Con el driver síncrono, create_async_engine falla con «The asyncio extension requires an async driver».

2

create_async_engine

Equivalente asíncrono de create_engine. Ya no hace falta check_same_thread: no hay varios hilos compartiendo la conexión.

3

async_sessionmaker(class_=AsyncSession)

Fábrica de sesiones asíncronas. Cada petición sigue teniendo la suya.

4

expire_on_commit=False

Aquí deja de ser una comodidad y pasa a ser obligatorio: con los objetos caducados, leer un atributo tras el commit dispararía E/S implícita y fallaría.

5

async with FabricaDeSesiones()

El gestor de contexto asíncrono cierra la sesión al salir, incluso ante una excepción. Sustituye al try/finally de la versión síncrona.

6

await sesion.scalars(consulta)

Ahora la ejecución de la consulta se espera. Olvidar el await devuelve una corrutina en lugar de los datos.

7

await sesion.get / commit / delete

Todas las operaciones que tocan la base pasan a esperarse. Las que solo construyen la consulta —select(), where()— siguen siendo síncronas.

8

lazy="joined" en las relaciones

En async no puede haber carga perezosa sobre un atributo que se vaya a leer: se resuelve con una consulta implícita fuera del await y aparece MissingGreenlet.

9

refresh(attribute_names=[…])

Tras el commit hay que recargar explícitamente las relaciones que la respuesta necesita; el refresh sin argumentos no las trae.

10

async def en el endpoint

Necesario porque su cuerpo usa await. Un endpoint que llame a una función asíncrona sin ser async def devolvería la corrutina sin ejecutar.

11

motor.begin() + run_sync

La creación de tablas es una operación DDL síncrona de SQLAlchemy; run_sync la ejecuta dentro del contexto asíncrono.

12

await motor.dispose()

Cierra el pool de forma ordenada al apagar la aplicación.

5. Errores comunes y cómo evitarlos

Olvidar un await: la función devuelve un objeto coroutine y aparece «object ChunkedIteratorResult can't be used in 'await' expression» o una respuesta con un objeto no serializable.

Mantener el driver síncrono en la URL: «InvalidRequestError: The asyncio extension requires an async driver to be used».

Recorrer una relación perezosa en async: «MissingGreenlet: greenlet_spawn has not been called». Se resuelve con lazy="joined", selectinload() o cargando el dato en la consulta.

Dejar expire_on_commit en su valor por defecto: tras el commit, cualquier lectura de atributo intenta ir a la base y falla.

Llamar a una librería síncrona bloqueante dentro de un async def —requests, time.sleep, una inferencia de scikit-learn—: se bloquea el bucle de eventos y se degrada toda la aplicación.

Convertir a async def endpoints que no hacen ningún await: no se gana nada y se pierde la ejecución en pool de hilos que FastAPI aplica a los def.

Compartir una AsyncSession entre tareas concurrentes: no es segura para uso concurrente; cada tarea necesita la suya.

Medir el rendimiento con una sola petición y concluir que async no sirve: la ganancia solo se ve con concurrencia.
