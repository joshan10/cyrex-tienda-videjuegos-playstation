1. Objetivo de la sesión

Al finalizar esta sesión, el aprendiz será capaz de implementar un CRUD completo en FastAPI usando el verbo y el código de estado adecuados a cada operación, controlar la forma de la respuesta con response_model y separar las operaciones sobre los datos en una capa propia, independiente de los endpoints.

2. Verbos, códigos de estado y forma de la respuesta

Verbo

Éxito

Cuerpo

Semántica

GET

200 OK

El recurso

Consulta. No modifica nada; repetirla no cambia el resultado.

POST

201 Created

El recurso creado

Crea. No es idempotente: dos llamadas iguales crean dos recursos.

PUT

200 OK

El recurso completo

Reemplaza el recurso entero. Es idempotente: repetirla deja el mismo estado.

PATCH

200 OK

El recurso actualizado

Modifica solo los campos enviados. El resto permanece intacto.

DELETE

204 No Content

Vacío

Elimina. La respuesta no lleva cuerpo, por definición del código 204.

Código

Nombre

Cuándo usarlo en BiblioAPI

400

Bad Request

La petición está mal formada a nivel de protocolo. Rara vez lo generamos a mano.

404

Not Found

El identificador solicitado no corresponde a ningún recurso.

409

Conflict

Los datos son válidos, pero el estado del sistema impide la operación: ISBN duplicado, libro con préstamos activos.

422

Unprocessable Entity

Los datos no cumplen el esquema. Lo genera FastAPI automáticamente; no hay que escribirlo.

Idea clave

La diferencia entre 409 y 422 es la que separa una regla de negocio de una regla de formato. Un ISBN de doce dígitos es 422 —el dato está mal escrito—. Un ISBN de trece dígitos que ya existe en el catálogo es 409 —el dato está bien escrito, pero el sistema no admite esa operación ahora—.

Equivalencia con Django REST Framework

Un ModelViewSet de DRF generaba las cinco operaciones con sus códigos correctos sin escribir nada: list, retrieve, create, update, partial_update y destroy salían del registro en el router. En FastAPI cada endpoint se declara a mano y el código de estado se indica explícitamente con status_code. Se gana visibilidad —todo lo que hace la API está escrito— y se pierde automatismo: si no se declara status_code=201, el POST responderá 200 y nadie avisará del error.

"""Operaciones sobre el catálogo. Hoy en memoria; en septiembre contra la base de datos."""

from itertools import count

from app.datos import LIBROS

# Generador de identificadores: continúa después del mayor id existente

_siguiente_id = count(max((libro["id"] for libro in LIBROS), default=0) + 1)

def listar() -> list[dict]:

 return LIBROS

def obtener(libro_id: int) -> dict | None:

 for libro in LIBROS:

 if libro["id"] == libro_id:

 return libro

 return None

def existe_isbn(isbn: str, excluir_id: int | None = None) -> bool:

 """Comprueba si el ISBN ya está en uso por otro libro distinto."""

 return any(

 libro["isbn"] == isbn and libro["id"] != excluir_id for libro in LIBROS

 )

def crear(datos: dict) -> dict:

 libro = {

 "id": next(_siguiente_id),

 **datos,

 "ejemplares_disponibles": datos["ejemplares_totales"],

 }

 LIBROS.append(libro)

 return libro

def reemplazar(libro_id: int, datos: dict) -> dict | None:

 """PUT: sustituye todos los campos editables del libro."""

 libro = obtener(libro_id)

 if libro is None:

 return None

 prestados = libro["ejemplares_totales"] - libro["ejemplares_disponibles"]

 libro.update(datos)

 libro["ejemplares_disponibles"] = max(datos["ejemplares_totales"] - prestados, 0)

 return libro

def actualizar(libro_id: int, cambios: dict) -> dict | None:

 """PATCH: aplica únicamente los campos enviados por el cliente."""

 libro = obtener(libro_id)

 if libro is None:

 return None

 if "ejemplares_totales" in cambios:

 prestados = libro["ejemplares_totales"] - libro["ejemplares_disponibles"]

 libro["ejemplares_disponibles"] = max(

 cambios["ejemplares_totales"] - prestados, 0

 )

 libro.update(cambios)

 return libro

def eliminar(libro_id: int) -> bool:

 libro = obtener(libro_id)

 if libro is None:

 return False

 LIBROS.remove(libro)

 return True

def tiene_prestamos_activos(libro_id: int) -> bool:

 """Provisional: se implementará de verdad con el recurso Préstamo."""

 libro = obtener(libro_id)

 if libro is None:

 return False

 return libro["ejemplares_disponibles"] < libro["ejemplares_totales"]

app/main.py — bloque del recurso Libro, actualizado

from typing import Annotated

from fastapi import FastAPI, HTTPException, Path, Query, Response, status

from app.crud import libros as crud_libros

from app.schemas.libro import LibroActualizar, LibroCrear, LibroRespuesta

app = FastAPI(

 title="BiblioAPI",

 description="API de gestión de préstamos de una biblioteca.",

 version="0.3.0",

)

@app.get("/libros", response_model=list[LibroRespuesta])

def listar_libros(

 categoria: Annotated[str | None, Query()] = None,

 solo_disponibles: Annotated[bool, Query()] = False,

 limite: Annotated[int, Query(ge=1, le=50)] = 10,

 desplazamiento: Annotated[int, Query(ge=0)] = 0,

):

 """Lista el catálogo aplicando filtros opcionales y paginación."""

 resultado = crud_libros.listar()

 if categoria is not None:

 resultado = [l for l in resultado if l["categoria"] == categoria]

 if solo_disponibles:

 resultado = [l for l in resultado if l["ejemplares_disponibles"] > 0]

 return resultado[desplazamiento : desplazamiento + limite]

@app.get("/libros/{libro_id}", response_model=LibroRespuesta)

def obtener_libro(libro_id: Annotated[int, Path(ge=1)]):

 """Devuelve el detalle de un libro por su identificador."""

 libro = crud_libros.obtener(libro_id)

 if libro is None:

 raise HTTPException(

 status_code=status.HTTP_404_NOT_FOUND,

 detail=f"No existe un libro con id {libro_id}.",

 )

 return libro

@app.post(

 "/libros",

 response_model=LibroRespuesta,

 status_code=status.HTTP_201_CREATED,

)

def crear_libro(datos: LibroCrear):

 if crud_libros.existe_isbn(datos.isbn):

 raise HTTPException(

 status_code=status.HTTP_409_CONFLICT,

 detail=f"Ya existe un libro registrado con el ISBN {datos.isbn}.",

 )

 return crud_libros.crear(datos.model_dump())

@app.put("/libros/{libro_id}", response_model=LibroRespuesta)

def reemplazar_libro(libro_id: Annotated[int, Path(ge=1)], datos: LibroCrear):

 """Reemplaza por completo los datos editables de un libro."""

 if crud_libros.existe_isbn(datos.isbn, excluir_id=libro_id):

 raise HTTPException(

 status_code=status.HTTP_409_CONFLICT,

 detail=f"El ISBN {datos.isbn} pertenece a otro libro.",

 )

 libro = crud_libros.reemplazar(libro_id, datos.model_dump())

 if libro is None:

 raise HTTPException(

 status_code=status.HTTP_404_NOT_FOUND,

 detail=f"No existe un libro con id {libro_id}.",

 )

 return libro

@app.patch("/libros/{libro_id}", response_model=LibroRespuesta)

def actualizar_libro(libro_id: Annotated[int, Path(ge=1)], datos: LibroActualizar):

 """Modifica únicamente los campos enviados."""

 cambios = datos.model_dump(exclude_unset=True)

 libro = crud_libros.actualizar(libro_id, cambios)

 if libro is None:

 raise HTTPException(

 status_code=status.HTTP_404_NOT_FOUND,

 detail=f"No existe un libro con id {libro_id}.",

 )

 return libro

@app.delete("/libros/{libro_id}", status_code=status.HTTP_204_NO_CONTENT)

def eliminar_libro(libro_id: Annotated[int, Path(ge=1)]):

 """Elimina un libro que no tenga ejemplares prestados."""

 if crud_libros.obtener(libro_id) is None:

 raise HTTPException(

 status_code=status.HTTP_404_NOT_FOUND,

 detail=f"No existe un libro con id {libro_id}.",

 )

 if crud_libros.tiene_prestamos_activos(libro_id):

 raise HTTPException(

 status_code=status.HTTP_409_CONFLICT,

 detail="No se puede eliminar un libro con ejemplares prestados.",

 )

 crud_libros.eliminar(libro_id)

 return Response(status_code=status.HTTP_204_NO_CONTENT)

# Crear un libro → 201

curl -i -X POST http://127.0.0.1:8000/libros \

 -H "Content-Type: application/json" \

 -d '{"titulo":"Delirio","isbn":"9788483462744","anio_publicacion":2004,

 "autor":"Laura Restrepo","categoria":"novela","ejemplares_totales":4}'

# HTTP/1.1 201 Created

# {"titulo":"Delirio","isbn":"9788483462744","anio_publicacion":2004,

# "autor":"Laura Restrepo","categoria":"novela","id":5,

# "ejemplares_totales":4,"ejemplares_disponibles":4}

# Repetir la misma petición → 409 (ISBN duplicado)

# {"detail":"Ya existe un libro registrado con el ISBN 9788483462744."}

# Actualización parcial → 200

curl -X PATCH http://127.0.0.1:8000/libros/5 \

 -H "Content-Type: application/json" -d '{"ejemplares_totales": 6}'

# {"...","ejemplares_totales":6,"ejemplares_disponibles":6}

# PATCH vacío → 422 (lo impide el model_validator del esquema)

curl -X PATCH http://127.0.0.1:8000/libros/5 \

 -H "Content-Type: application/json" -d '{}'

# Eliminar → 204 sin cuerpo

curl -i -X DELETE http://127.0.0.1:8000/libros/5

# HTTP/1.1 204 No Content

4. Ejemplo detallado: explicación línea por línea

N°

Elemento

Explicación

1

def crear_libro(datos: LibroCrear)

El parámetro no es un query ni un path param: al ser un modelo Pydantic, FastAPI entiende que viaja en el cuerpo de la petición y lo valida antes de ejecutar la función.

2

response_model=LibroRespuesta

Filtra la salida: aunque el diccionario interno tenga campos extra, solo se devuelven los declarados en el esquema. Es la protección contra fugas de datos.

3

status_code=status.HTTP_201_CREATED

Sin esta línea el POST respondería 200. Usar la constante en vez del número literal hace el código legible y evita erratas.

4

from fastapi import status

Colección de constantes con nombre para todos los códigos HTTP. status.HTTP_409_CONFLICT se explica solo; 409 hay que recordarlo.

5

datos.model_dump()

Convierte el modelo validado en un diccionario. Es la frontera entre la capa de esquemas y la capa de datos.

6

model_dump(exclude_unset=True)

En el PATCH devuelve solo lo que el cliente envió. Sin exclude_unset, los campos no enviados llegarían como None y borrarían los valores existentes.

7

existe_isbn(..., excluir_id=libro_id)

Al reemplazar un libro, su propio ISBN no debe contar como duplicado. Sin excluir_id, un PUT sin cambios respondería 409.

8

prestados = totales - disponibles

Al cambiar el número de ejemplares totales hay que preservar cuántos están prestados; recalcular disponibles a ciegas perdería esa información.

9

status_code=204 en el decorador

Declara que la respuesta no lleva cuerpo. Devolver un diccionario en un endpoint 204 provoca un error de contenido inesperado.

10

app/crud/libros.py separado

Los endpoints traducen HTTP; el módulo crud manipula los datos. Gracias a esa separación, en septiembre cambiaremos la memoria por SQLAlchemy sin tocar los endpoints.

5. Errores comunes y cómo evitarlos

Olvidar status_code=201 en el POST: la API responde 200 y cualquier cliente que distinga creación de consulta queda desinformado.

Usar model_dump() sin exclude_unset en el PATCH: los campos ausentes llegan como None y sobrescriben datos válidos con nulos.

Devolver un cuerpo en un endpoint declarado con 204: FastAPI emite «Response content longer than Content-Length» o el cliente recibe una respuesta malformada.

Confundir PUT con PATCH: si PUT admite campos parciales deja de ser idempotente y de reemplazar, y el cliente pierde la garantía que ese verbo promete.

Responder 400 o 500 ante un ISBN duplicado. Es un conflicto de estado: 409.

Poner la lógica de datos dentro del endpoint. Cuando llegue la base de datos habría que reescribir cada función de ruta en lugar de un solo módulo.
