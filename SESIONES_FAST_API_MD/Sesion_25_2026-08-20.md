Tema de la sesión

Modelos de datos con Pydantic

1. Objetivo de la sesión

Al finalizar esta sesión, el aprendiz será capaz de definir esquemas de datos con Pydantic v2 usando BaseModel y Field, escribir validadores propios con field_validator y model_validator, y separar los esquemas de creación, actualización y respuesta para controlar con precisión qué entra y qué sale de la API.

2. Esquemas: el contrato de datos de la API

Hasta ahora los libros son diccionarios sueltos: nada impide que a uno le falte el ISBN o que otro tenga el año como texto. Un esquema Pydantic es una clase que declara la forma exacta del dato, la valida al recibirla y la serializa al devolverla.

Elemento

Función

BaseModel

Clase base de todo esquema. Los atributos declarados con su tipo definen los campos.

Field()

Añade restricciones y metadatos a un campo: rangos, longitudes, descripción y ejemplos para /docs.

field_validator

Valida un campo concreto con lógica propia, más allá de lo que expresan los tipos y Field.

model_validator

Valida el modelo completo: reglas que dependen de la relación entre varios campos.

model_config

Configuración del esquema. Sustituye a la antigua clase interna Config.

from_attributes

Permite construir un esquema a partir de un objeto con atributos, no solo de un diccionario. Lo necesitaremos con SQLAlchemy.

Idea clave

Un esquema por operación, no un esquema para todo. El cliente no envía el id al crear, no está obligado a enviar todos los campos al actualizar, y no debe recibir campos internos en la respuesta. Un único modelo compartido obliga a hacer opcional todo lo que en algún caso lo es, y con ello se pierde la validación.

from datetime import date

from typing import Literal

from pydantic import BaseModel, ConfigDict, Field, field_validator, model_validator

Categoria = Literal["novela", "memorias", "tecnica", "infantil", "referencia"]

class LibroBase(BaseModel):

 """Campos comunes a la creación y la respuesta."""

 titulo: str = Field(

 min_length=1,

 max_length=200,

 description="Título del libro tal como aparece en la portada.",

 )

 isbn: str = Field(

 pattern=r"^\d{13}$",

 description="ISBN-13, exactamente 13 dígitos sin guiones.",

 )

 anio_publicacion: int = Field(ge=1450, le=date.today().year)

 autor: str = Field(min_length=3, max_length=120)

 categoria: Categoria

 @field_validator("titulo", "autor")

 @classmethod

 def sin_espacios_sobrantes(cls, valor: str) -> str:

 """Normaliza el texto: recorta extremos y colapsa espacios internos."""

 return " ".join(valor.split())

class LibroCrear(LibroBase):

 """Lo que el cliente envía al registrar un libro nuevo."""

 ejemplares_totales: int = Field(ge=1, le=999)

class LibroActualizar(BaseModel):

 """Actualización parcial: todos los campos son opcionales."""

 titulo: str | None = Field(default=None, min_length=1, max_length=200)

 autor: str | None = Field(default=None, min_length=3, max_length=120)

 categoria: Categoria | None = None

 ejemplares_totales: int | None = Field(default=None, ge=1, le=999)

 @model_validator(mode="after")

 def al_menos_un_campo(self):

 """Impide una actualización vacía, que sería una petición sin efecto."""

 if not self.model_dump(exclude_unset=True):

 raise ValueError("Debe enviarse al menos un campo para actualizar.")

 return self

class LibroRespuesta(LibroBase):

 """Lo que la API devuelve. Incluye los campos calculados por el servidor."""

 model_config = ConfigDict(from_attributes=True)

 id: int

 ejemplares_totales: int

 ejemplares_disponibles: int

 @model_validator(mode="after")

 def disponibles_no_superan_totales(self):

 if self.ejemplares_disponibles > self.ejemplares_totales:

 raise ValueError(

 "Los ejemplares disponibles no pueden superar los totales."

 )

 return self

4. Ejemplo detallado: explicación línea por línea

N°

Elemento

Explicación

1

Literal["novela", …]

Restringe el valor a un conjunto cerrado. En /docs aparece como una lista desplegable, y cualquier otro valor produce 422.

2

Field(min_length=1, max_length=200)

Restricciones declarativas del campo. No requieren escribir ningún if.

3

pattern=r"^\d{13}$"

Expresión regular que exige exactamente trece dígitos. El anclaje ^…$ es imprescindible: sin él, «abc9780307474728» pasaría la validación.

4

le=date.today().year

El límite superior se calcula al importar el módulo, no se escribe fijo. Así el código no caduca el 1 de enero.

5

@field_validator("titulo", "autor")

Un mismo validador aplicado a varios campos. Debe ir acompañado de @classmethod: es un requisito de Pydantic v2.

6

" ".join(valor.split())

Normaliza: recorta los extremos y reduce los espacios internos a uno. Los validadores pueden transformar el dato, no solo aceptarlo o rechazarlo.

7

LibroCrear(LibroBase)

Hereda todos los campos comunes y añade ejemplares_totales. La herencia evita repetir el contrato en cada esquema.

8

@model_validator(mode="after")

Se ejecuta cuando todos los campos ya fueron validados individualmente, por eso puede compararlos entre sí. Devuelve self, no un diccionario.

9

model_dump(exclude_unset=True)

Devuelve solo los campos que el cliente envió de forma explícita. Es la clave del PATCH: distingue «no lo mandó» de «lo mandó en null».

10

ConfigDict(from_attributes=True)

Permite construir la respuesta desde un objeto con atributos. Hoy no cambia nada porque trabajamos con diccionarios; será imprescindible con SQLAlchemy.

11

id en LibroRespuesta

Aparece solo en la respuesta. El cliente nunca envía el identificador: lo asigna el servidor.

5. Errores comunes y cómo evitarlos

Usar @validator en lugar de @field_validator: en Pydantic v2 produce «PydanticUserError: The `@validator` decorator is removed». Es sintaxis de la versión 1.

Olvidar @classmethod bajo @field_validator: aparece «PydanticUserError: `@field_validator` cannot be applied to instance methods».

Reutilizar un único esquema para crear, actualizar y responder: obliga a declarar opcionales campos que son obligatorios al crear, y la validación deja de proteger nada.

Escribir la expresión regular sin anclajes (r"\d{13}"): valida que el ISBN contenga trece dígitos en alguna parte, no que sea exactamente eso.

Devolver el diccionario interno tal cual en lugar del esquema de respuesta: se filtran campos que no deberían salir, como el correo o el documento de un socio.

Usar .dict() sobre el modelo: en Pydantic v2 el método es model_dump(); .dict() está obsoleto y emite una advertencia de deprecación.
