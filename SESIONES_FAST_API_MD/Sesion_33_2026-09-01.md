Tema de la sesión

Autenticación y autorización (OAuth2 / JWT)

1. Objetivo de la sesión

Al finalizar esta sesión, el aprendiz será capaz de implementar el flujo OAuth2 con contraseña en FastAPI: almacenar contraseñas mediante un algoritmo de hash moderno, emitir tokens JWT firmados, validarlos en cada petición a través de una dependencia y restringir el acceso a los endpoints según el rol del usuario autenticado.

2. Autenticación, autorización y el papel del token

Desde el 27 de agosto la identidad viaja en la cabecera X-Socio-Id, que cualquiera puede escribir a mano. Hoy se sustituye por un token firmado: sigue siendo una cabecera, pero su contenido no puede alterarse sin invalidar la firma.

Concepto

Descripción

Autenticación

Establecer quién es el solicitante. Falla con 401 Unauthorized.

Autorización

Decidir si ese solicitante puede realizar la operación. Falla con 403 Forbidden.

Hash de contraseña

Transformación irreversible. La base guarda el hash, nunca la contraseña. Argon2 y bcrypt incorporan sal y coste computacional.

JWT

Cadena de tres partes —cabecera, carga útil y firma— separadas por puntos y codificadas en Base64URL.

Carga útil (claims)

Datos del token: sub (sujeto), exp (expiración), y los que añada la aplicación, como el rol.

Firma

HMAC de las dos primeras partes con la clave secreta. Garantiza que nadie alteró el contenido.

Bearer

Esquema de envío: Authorization: Bearer <token> en cada petición.

Idea clave

Un JWT está firmado, no cifrado. Cualquiera puede leer su contenido pegándolo en un decodificador: lo que no puede es modificarlo sin la clave secreta. Por eso nunca se guardan datos sensibles en la carga útil, y por eso la clave secreta jamás se escribe en el código.

La diferencia de fondo: DRF traía un modelo de usuario y un sistema de permisos ya montados. FastAPI no impone ninguno, así que el modelo de usuario, el almacenamiento de la contraseña y la política de acceso los define el equipo. Más trabajo inicial, y ningún comportamiento oculto.

app/core/seguridad.py — nuevo archivo

from datetime import datetime, timedelta, timezone

import jwt

from pwdlib import PasswordHash

from app.core.configuracion import configuracion

# Argon2 como algoritmo recomendado; verifica también hashes antiguos de bcrypt

gestor_de_hash = PasswordHash.recommended()

def hashear_contrasena(contrasena: str) -> str:

 return gestor_de_hash.hash(contrasena)

def verificar_contrasena(contrasena: str, hash_almacenado: str) -> bool:

 return gestor_de_hash.verify(contrasena, hash_almacenado)

def crear_token(socio_id: int, rol: str) -> str:

 """Emite un JWT firmado con el identificador y el rol del socio."""

 ahora = datetime.now(timezone.utc)

 carga = {

 "sub": str(socio_id),

 "rol": rol,

 "iat": ahora,

 "exp": ahora + timedelta(minutes=configuracion.minutos_expiracion_token),

 }

 return jwt.encode(

 carga,

 configuracion.secret_key,

 algorithm=configuracion.algoritmo_jwt,

 )

def decodificar_token(token: str) -> dict:

 """Verifica la firma y la expiración. Propaga la excepción si algo falla."""

 return jwt.decode(

 token,

 configuracion.secret_key,

 algorithms=[configuracion.algoritmo_jwt],

 )

router = APIRouter(

 prefix="/auth",

 tags=["Autenticación"],

 responses={401: {"model": DetalleDeError}},

)

@router.post(

 "/token",

 response_model=Token,

 summary="Obtener un token de acceso",

 description=(

 "Flujo OAuth2 con contraseña. El campo username corresponde al "

 "número de documento del socio."

 ),

)

def iniciar_sesion(

 formulario: Annotated[OAuth2PasswordRequestForm, Depends()],

):

 socio = buscar_socio_por_documento(formulario.username)

 # Mismo mensaje si el documento no existe o si la contraseña es incorrecta:

 raise NoAutenticado("La cuenta está inactiva.")

 acceso=crear_token(socio_id=socio["id"], rol=socio["rol"]),

 expira_en_segundos=configuracion.minutos_expiracion_token * 60,

 )

 "/yo",

 response_model=SocioAutenticado,

 summary="Datos del socio autenticado",

 return socio

app/dependencias.py — la identidad ahora viene del token

from typing import Annotated

import jwt

from fastapi import Depends

from fastapi.security import OAuth2PasswordBearer

from app.core.seguridad import decodificar_token

from app.datos import buscar_socio_por_id

from app.errores import NoAutenticado, PermisoDenegado

# tokenUrl no se usa en el código: le indica a /docs dónde pedir el token,

# lo que activa el botón «Authorize» de Swagger UI.

esquema_oauth2 = OAuth2PasswordBearer(tokenUrl="auth/token")

def socio_actual(

 token: Annotated[str, Depends(esquema_oauth2)],

) -> dict:

 """Valida el token y devuelve el socio correspondiente."""

 try:

 carga = decodificar_token(token)

 except jwt.ExpiredSignatureError:

 raise NoAutenticado("El token expiró. Inicie sesión de nuevo.")

 except jwt.InvalidTokenError:

 raise NoAutenticado("El token no es válido.")

 socio_id = carga.get("sub")

 if socio_id is None:

 raise NoAutenticado("El token no identifica a ningún socio.")

 socio = buscar_socio_por_id(int(socio_id))

 if socio is None:

 raise NoAutenticado("El socio del token ya no existe.")

 if not socio["activo"]:

 raise NoAutenticado("La cuenta está inactiva.")

 return socio

def exigir_bibliotecario(

 socio: Annotated[dict, Depends(socio_actual)],

) -> dict:

 """Autorización: la identidad ya está establecida; aquí se decide el permiso."""

 if socio["rol"] != "bibliotecario":

 raise PermisoDenegado(

 "Esta operación está reservada al personal de la biblioteca."

 )

 return socio

SocioActual = Annotated[dict, Depends(socio_actual)]

Bibliotecario = Annotated[dict, Depends(exigir_bibliotecario)]

4. Ejemplo detallado: explicación línea por línea

N°

Elemento

Explicación

1

secret_key: str sin valor por defecto

Si la variable de entorno falta, Configuracion falla al construirse y la aplicación no arranca. Es preferible a arrancar con una clave conocida.

2

PasswordHash.recommended()

Devuelve el gestor con Argon2 como algoritmo principal. Verifica además hashes bcrypt antiguos, lo que permite migrar sin invalidar contraseñas existentes.

3

hash y verify

El hash incluye la sal y los parámetros de coste dentro de la propia cadena; por eso verify no necesita nada más que la contraseña y el hash.

4

"sub": str(socio_id)

La especificación de JWT exige que sub sea una cadena. PyJWT 2.10 rechaza un entero al decodificar.

5

"exp": ahora + timedelta(...)

Expiración obligatoria. Un token sin exp es válido para siempre, incluso si el usuario cambia su contraseña.

6

datetime.now(timezone.utc)

Siempre en UTC. Un exp calculado en hora local produce tokens que caducan antes o después de lo previsto según el servidor.

7

OAuth2PasswordRequestForm

Lee username y password de un formulario, no de JSON. Es lo que exige el estándar OAuth2 y lo que espera el botón Authorize de Swagger UI.

8

Mismo mensaje para usuario y contraseña

Distinguirlos convierte el endpoint en un verificador de qué documentos están registrados.

9

OAuth2PasswordBearer(tokenUrl=...)

Extrae el token de la cabecera Authorization y documenta el flujo. La ruta indicada solo se usa para la documentación.

10

except jwt.ExpiredSignatureError

Se distingue del token inválido porque el mensaje al usuario es distinto: uno se resuelve iniciando sesión otra vez.

11

socio_actual comprueba activo

El token pudo emitirse antes de que la cuenta se desactivara. La validez del token no equivale a la vigencia de la cuenta.

12

exigir_bibliotecario depende de socio_actual

Autenticación y autorización quedan en funciones distintas: primero quién es, después qué puede hacer.

13

WWW-Authenticate: Bearer

Cabecera que la especificación de HTTP exige acompañando a un 401. Indica al cliente qué esquema de autenticación usar.

5. Errores comunes y cómo evitarlos

Escribir la clave secreta en el código o darle un valor por defecto: cualquiera con acceso al repositorio puede firmar tokens válidos.

Guardar la contraseña en claro o con un hash rápido como MD5 o SHA-256 sin sal: están diseñados para ser veloces, justo lo contrario de lo que conviene aquí.

Emitir tokens sin exp: siguen siendo válidos indefinidamente y no hay forma de revocarlos.

Poner el identificador como entero en sub: PyJWT 2.10 lanza «Subject must be a string» al decodificar.

Enviar las credenciales como JSON al endpoint del token: OAuth2PasswordRequestForm espera un formulario, y sin python-multipart instalado FastAPI lanza «Form data requires python-multipart».

Devolver 403 cuando falta el token: si no se sabe quién es el solicitante, corresponde 401. El 403 es para identidades conocidas sin permiso.

Guardar datos sensibles en la carga útil del token creyendo que va cifrado: es solo Base64, legible por cualquiera.

Olvidar comprobar que la cuenta sigue activa: un token emitido antes de la desactivación seguiría abriendo la puerta hasta su expiración.
