Introducción a APIs REST

El recurso es un sustantivo y la acción es el verbo. El código de estado forma parte de la respuesta: 201 al crear, 204 al eliminar, 404 cuando no existe, 409 ante un conflicto de negocio y 422 cuando los datos no validan.

Primeros pasos con FastAPI

Entorno virtual, instalación, estructura app/main.py, decoradores de ruta, uvicorn --reload y documentación automática en /docs y /redoc.

Path y query params

El path identifica, el query filtra. Annotated separa el tipo de la restricción; FastAPI valida antes de ejecutar la función.

Idea clave

Las tres sesiones apuntan a lo mismo: en FastAPI se declara lo que se espera y el framework se encarga de hacerlo cumplir. Cuando aparezca la tentación de validar a mano dentro de la función, casi siempre existe una forma declarativa de hacerlo.

Preguntas de diagnóstico

N°

Pregunta

Respuesta esperada

1

¿Por qué /libros/eliminar/3 es una ruta mal diseñada?

Porque pone la acción en la ruta. La acción la expresa el verbo: DELETE /libros/3.

2

Un socio intenta pedir un cuarto préstamo simultáneo. ¿Qué código responde la API?

409 Conflict: los datos son válidos, pero el estado del sistema impide la operación. No es 422 ni 400.

3

¿Qué diferencia hay entre 401 y 403?

401 es «no sé quién eres» (falta o es inválida la credencial); 403 es «sé quién eres y no te corresponde».

4

¿Qué ocurre si se pide GET /libros/abc?

FastAPI responde 422 antes de ejecutar la función, porque abc no puede convertirse al entero declarado.

5

¿Por qué falla uvicorn app.main:app ejecutado dentro de la carpeta app?

Porque la ruta de importación se resuelve desde el directorio actual y ahí no existe el paquete app. Se lanza desde la raíz del proyecto.

6

¿Para qué sirve = None al final de un query param?

Lo convierte en opcional. Sin valor por defecto, el parámetro es obligatorio y su ausencia produce 422.

7

¿De dónde sale el contenido de /docs?

Del esquema OpenAPI que FastAPI genera a partir de los tipos declarados, los metadatos de Query/Path y los docstrings de las funciones.

8

¿Por qué el orden de declaración de las rutas importa?

Porque se evalúan en orden: una ruta con parámetro declarada antes puede capturar peticiones destinadas a una ruta fija posterior.

from app.datos import SOCIOS, buscar_socio_por_id # añadir al import existente

@app.get("/socios")

def listar_socios(

 activo: Annotated[

 bool | None,

 Query(description="Filtra por estado del socio."),

 ] = None,

 rol: Annotated[

 str | None,

 Query(description="socio o bibliotecario."),

 ] = None,

 limite: Annotated[int, Query(ge=1, le=50)] = 10,

 desplazamiento: Annotated[int, Query(ge=0)] = 0,

):

 """Lista los socios registrados con filtros opcionales."""

 resultado = SOCIOS

 if activo is not None:

 resultado = [s for s in resultado if s["activo"] == activo]

 if rol is not None:

 resultado = [s for s in resultado if s["rol"] == rol]

 return {

 "total": len(resultado),

 "limite": limite,

 "desplazamiento": desplazamiento,

 "resultados": resultado[desplazamiento : desplazamiento + limite],

 }

@app.get("/socios/{socio_id}")

def obtener_socio(

 socio_id: Annotated[int, Path(ge=1, description="Identificador del socio.")],

):

 """Devuelve el detalle de un socio por su identificador."""

 socio = buscar_socio_por_id(socio_id)

 if socio is None:

 raise HTTPException(

 status_code=404,

 detail=f"No existe un socio con id {socio_id}.",

 )

 return socio

4. Errores comunes recopilados de las sesiones anteriores

Rutas con verbos o en singular. Revisar que todas las colecciones estén en plural y que ninguna ruta contenga crear, obtener, listar o eliminar.

Devolver 200 al crear un recurso. Cuando lleguemos al POST, la respuesta correcta es 201 con el recurso creado en el cuerpo.

Validar a mano dentro de la función lo que Query() o Path() ya validan de forma declarativa.

Olvidar app/__init__.py o ejecutar uvicorn desde la carpeta equivocada: «ModuleNotFoundError: No module named 'app'».

Declarar la ruta con parámetro antes que la ruta fija y recibir 422 donde se esperaba una respuesta correcta.

Mantener el catálogo dentro de main.py. El archivo debe quedar solo con la aplicación y los endpoints; los datos viven en app/datos.py.
