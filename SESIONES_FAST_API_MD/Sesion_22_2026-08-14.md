Primeros pasos con FastAPI

1. Objetivo de la sesión

Al finalizar esta sesión, el aprendiz será capaz de crear un proyecto FastAPI desde cero: preparar el entorno virtual, instalar las dependencias, escribir sus primeros endpoints, levantar el servidor con uvicorn en modo recarga automática y consultar la documentación interactiva que el framework genera por sí solo.

2. Qué es FastAPI y qué cambia frente a Django REST Framework

FastAPI es un framework web para construir APIs con Python moderno. Su idea central es aprovechar las anotaciones de tipo del lenguaje: al declarar que un parámetro es un entero, el framework valida la entrada, convierte el dato y documenta el endpoint automáticamente, sin configuración adicional.

Componente

Función

FastAPI

El framework: define la aplicación, las rutas y la validación a partir de los tipos declarados.

Starlette

La base sobre la que corre FastAPI: enrutamiento, middlewares y soporte asíncrono.

Pydantic

La librería de validación y serialización. Sustituye el papel de los serializers de DRF.

Uvicorn

El servidor ASGI que ejecuta la aplicación. Equivale a runserver en desarrollo y a gunicorn en producción.

ASGI

El estándar sobre el que se apoya todo: permite manejar peticiones de forma asíncrona, algo que WSGI no contempla.

Idea clave

En FastAPI las anotaciones de tipo no son documentación decorativa: son la fuente única de la validación, la conversión de datos y la documentación OpenAPI. Escribir libro_id: int no es un comentario, es una regla que el framework hace cumplir.

La diferencia de fondo: DRF parte de un proyecto grande que se recorta; FastAPI parte de un archivo vacío que se hace crecer. No hay settings.py, ni apps registradas, ni migraciones iniciales.

3. Ejemplo guiado: arranque de BiblioAPI

Comandos a ejecutar

# 1. Crear la carpeta del proyecto y entrar en ella

mkdir biblioapi && cd biblioapi

# 2. Crear y activar el entorno virtual

python -m venv .venv

source .venv/bin/activate # Linux / macOS

.venv\Scripts\activate # Windows (PowerShell)

# 3. Instalar las dependencias

pip install "fastapi[standard]==0.115.6" "uvicorn[standard]==0.34.0"

# 4. Congelar las versiones instaladas

pip freeze > requirements.txt

mkdir app && touch app/__init__.py app/main.py

 version="0.1.0",

def raiz():

 """Punto de entrada: confirma que el servicio está arriba."""

 return {

 "servicio": "BiblioAPI",

 "documentacion": "/docs",

 }

 """Endpoint de monitoreo: lo consultará el orquestador en producción."""

 return {"estado": "ok"}

4. Ejemplo detallado: explicación línea por línea

N°

Elemento

Explicación

1

python -m venv .venv

Crea un entorno virtual aislado dentro del proyecto. Sin él, las dependencias se instalan en el Python del sistema y los proyectos terminan pisándose entre sí.

2

fastapi[standard]

Los corchetes instalan los extras recomendados (validación de correo, soporte de formularios, cliente de pruebas). Sin ellos, algunas funciones fallan al importarse.

3

app = FastAPI(...)

Instancia de la aplicación. Los argumentos title, description y version no son adorno: alimentan directamente el esquema OpenAPI y la cabecera de /docs.

4

@app.get("/")

Decorador que registra la función como manejador del verbo GET en esa ruta. El nombre de la función es libre; lo que define el endpoint es el decorador.

5

def raiz():

Función síncrona. FastAPI la ejecuta en un pool de hilos para no bloquear el bucle de eventos. Hasta el 7 de septiembre no necesitamos async def.

6

"""Punto de entrada…"""

El docstring se convierte en la descripción del endpoint dentro de /docs. Documentar la función es documentar la API.

7

return {...}

Se devuelve un diccionario de Python; FastAPI lo serializa a JSON y añade la cabecera Content-Type: application/json automáticamente.

8

uvicorn app.main:app

Ruta de importación: módulo app.main, objeto app dentro de él. Un error frecuente es escribir main:app estando fuera de la carpeta correcta.

9

--reload

Reinicia el servidor al detectar cambios en los archivos. Solo para desarrollo: en producción consume recursos y es innecesario.

5. Errores comunes y cómo evitarlos

Ejecutar uvicorn app.main:app desde dentro de la carpeta app. El error es «ModuleNotFoundError: No module named 'app'»; uvicorn se lanza desde la raíz del proyecto, no desde el paquete.

Olvidar el archivo app/__init__.py. Sin él, app deja de ser un paquete importable y aparece el mismo ModuleNotFoundError.

Instalar las dependencias con el entorno virtual sin activar: el paquete queda en el Python del sistema y al ejecutar uvicorn aparece «command not found» o una versión distinta de FastAPI.

Poner paréntesis al decorador incompleto: escribir @app.get sin la ruta produce «TypeError: get() missing 1 required positional argument: 'path'».

Dejar --reload en el comando de despliegue. En producción se usa uvicorn sin recarga, con varios workers o detrás de gunicorn.
