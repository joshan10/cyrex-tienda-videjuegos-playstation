Tema de la sesión

Middlewares, CORS y seguridad básica

1. Objetivo de la sesión

Al finalizar esta sesión, el aprendiz será capaz de escribir middlewares propios que intervengan en todas las peticiones de la API, configurar CORS para permitir el acceso desde un frontend externo sin abrir la aplicación a cualquier origen, y aplicar un conjunto mínimo de buenas prácticas de seguridad mediante cabeceras de respuesta y configuración por variables de entorno.

2. Middleware: el envoltorio de toda petición

Una dependencia se aplica a los endpoints que la declaran. Un middleware se aplica a todas las peticiones, incluidas las que terminan en 404 porque la ruta no existe. Se ejecuta antes de que la petición llegue al enrutador y después de que la respuesta se haya construido.

Concepto

Descripción

call_next

Función que continúa la cadena. Todo lo que va antes ocurre en la entrada; todo lo que va después, en la salida.

Orden de ejecución

Los middlewares se ejecutan en orden inverso al de registro: el último añadido es el más externo, el primero en ver la petición.

Middleware vs dependencia

El middleware no puede inyectar valores en el endpoint ni conoce qué ruta se ejecutó hasta después. Para reglas por endpoint, se usa una dependencia.

CORS

Mecanismo del navegador que impide a una página de un origen llamar a una API de otro origen salvo que la API lo autorice explícitamente en sus cabeceras.

Origen

La terna esquema + dominio + puerto. http://localhost:3000 y http://localhost:5173 son orígenes distintos.

Petición preflight

OPTIONS que el navegador envía antes de la petición real cuando esta no es simple. CORSMiddleware la responde automáticamente.

Idea clave

CORS es una restricción del navegador, no del servidor. Por eso curl y Postman funcionan aunque CORS esté mal configurado, y la aplicación web falla. Cuando un aprendiz reporte «la API funciona en Postman pero no desde React», la causa es casi siempre esta.

Equivalencia con Django REST Framework

En DRF instalaron django-cors-headers, lo añadieron a INSTALLED_APPS y a MIDDLEWARE en una posición precisa, y configuraron CORS_ALLOWED_ORIGINS en settings.py. La lógica es idéntica; cambia el envoltorio: aquí CORSMiddleware viene incluido en Starlette y se añade con app.add_middleware. Los middlewares propios, que en Django eran clases con __call__ y get_response, aquí son funciones decoradas con @app.middleware("http") que reciben call_next.

app/middlewares.py — nuevo archivo

import logging

import time

import uuid

from fastapi import Request

logger = logging.getLogger("biblioapi.peticiones")

async def registrar_peticion(peticion: Request, call_next):

 """Mide el tiempo de respuesta y registra cada petición con un identificador."""

 identificador = str(uuid.uuid4())[:8]

 inicio = time.perf_counter()

 respuesta = await call_next(peticion)

 duracion_ms = (time.perf_counter() - inicio) * 1000

 logger.info(

 "[%s] %s %s → %s (%.1f ms)",

 identificador,

 peticion.method,

 peticion.url.path,

 respuesta.status_code,

 duracion_ms,

 )

 respuesta.headers["X-Peticion-Id"] = identificador

 respuesta.headers["X-Tiempo-Respuesta-ms"] = f"{duracion_ms:.1f}"

 return respuesta

async def cabeceras_de_seguridad(peticion: Request, call_next):

 """Añade cabeceras defensivas a todas las respuestas."""

 respuesta = await call_next(peticion)

 respuesta.headers.setdefault("X-Content-Type-Options", "nosniff")

 respuesta.headers.setdefault("X-Frame-Options", "DENY")

 respuesta.headers.setdefault("Referrer-Policy", "no-referrer")

 respuesta.headers.setdefault(

 "Cache-Control", "no-store, no-cache, must-revalidate"

 )

 return respuesta

4. Ejemplo detallado: explicación línea por línea

N°

Elemento

Explicación

1

async def registrar_peticion(peticion, call_next)

Los middlewares son siempre asíncronos, aunque los endpoints sean síncronos. Es un requisito de la especificación ASGI.

2

respuesta = await call_next(peticion)

Punto de bifurcación: lo escrito antes ocurre en la entrada, lo escrito después en la salida, cuando la respuesta ya existe.

3

time.perf_counter()

Reloj monotónico de alta resolución, pensado para medir intervalos. time.time() puede retroceder si el sistema ajusta la hora.

4

uuid.uuid4()[:8]

Identificador corto por petición. Permite correlacionar la línea del log con la respuesta que recibió el cliente.

5

respuesta.headers["X-Peticion-Id"]

La cabecera se añade después de generar la respuesta. Antes de call_next todavía no existe ningún objeto respuesta.

6

headers.setdefault(...)

Solo fija la cabecera si nadie la puso antes; así un endpoint que necesite un Cache-Control distinto no queda pisado.

7

X-Content-Type-Options: nosniff

Impide que el navegador adivine el tipo de contenido, técnica usada para ejecutar como script una respuesta que no lo era.

8

X-Frame-Options: DENY

Bloquea la incrustación de las respuestas en un iframe, defensa básica contra clickjacking.

9

Orden de registro

cabeceras_de_seguridad se registra primero y registrar_peticion después, así que este último es el más externo y mide el tiempo total, incluido el de los demás middlewares.

10

allow_origins=configuracion.origenes_permitidos

La lista viene de la configuración, no escrita en el código: en producción se ajusta por variable de entorno sin tocar el código fuente.

11

allow_credentials=True

Permite que el navegador envíe cookies y cabecera Authorization. Es incompatible con allow_origins=["*"]: el navegador rechaza esa combinación.

12

expose_headers=[...]

Sin esta línea, el JavaScript del frontend no puede leer X-Peticion-Id aunque el servidor la envíe. Solo unas pocas cabeceras son visibles por defecto.

13

docs_url=None si no hay depuración

En producción no se publica la documentación interactiva: es un mapa completo de la API para cualquiera que la encuentre.

14

max_age=600

El navegador cachea el resultado del preflight diez minutos, evitando un OPTIONS antes de cada petición.

5. Errores comunes y cómo evitarlos

Combinar allow_origins=["*"] con allow_credentials=True: el navegador rechaza la respuesta con «The value of the 'Access-Control-Allow-Origin' header must not be the wildcard '*' when the request's credentials mode is 'include'».

Incluir la barra final en el origen ("http://localhost:3000/"): no coincide con el origen que envía el navegador y CORS falla sin mensaje evidente en el servidor.

Olvidar await antes de call_next: la respuesta es una corrutina sin ejecutar y aparece «AttributeError: 'coroutine' object has no attribute 'headers'».

Poner reglas de negocio en un middleware. No sabe qué endpoint se ejecutará ni puede inyectar valores; para eso están las dependencias.

Dejar docs_url activo y depuracion=True en producción: se publica el mapa completo de la API y las trazas de error quedan expuestas.

Versionar el archivo .env. Va en .gitignore; lo que se comparte es .env.example, con las claves y sin los valores.

Añadir un middleware pesado —una consulta a base de datos, por ejemplo— sin recordar que se ejecuta en cada petición, incluidas las que terminan en 404.
