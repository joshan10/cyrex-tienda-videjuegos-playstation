1. Objetivo de la sesión

Al finalizar esta sesión, el aprendiz será capaz de configurar la conexión a una base de datos con SQLAlchemy 2.0, definir modelos declarativos con Mapped y mapped_column, establecer relaciones entre tablas, y entregar la sesión de base de datos a los endpoints mediante una dependencia con ciclo de vida propio.

2. Las cuatro piezas de SQLAlchemy y una distinción esencial

Pieza

Función

Engine

Gestiona el pool de conexiones a la base. Se crea una sola vez, al arrancar la aplicación.

Session

Unidad de trabajo: acumula los cambios en memoria y los envía a la base al confirmar. Es de vida corta: una por petición.

DeclarativeBase

Clase base de la que heredan los modelos. Reúne los metadatos de todas las tablas.

Mapped / mapped_column

Sintaxis tipada de SQLAlchemy 2.0. El tipo de Python define el tipo de la columna; mapped_column añade restricciones.

relationship

Declara la relación entre modelos y permite navegarla como atributo: libro.autor devuelve el objeto Autor.

Idea clave

Modelo ORM y esquema Pydantic no son lo mismo ni sobran uno de los dos. El modelo describe cómo se guarda el dato —tablas, columnas, claves foráneas, índices—. El esquema describe cómo entra y sale por la API. Fusionarlos hace que cualquier cambio en la base rompa el contrato público, y que cualquier campo interno quede expuesto.

La diferencia práctica que más se nota: en Django la sesión y la conexión están ocultas, y el modelo sabe consultarse a sí mismo. En SQLAlchemy la sesión es un objeto explícito que hay que obtener, pasar y cerrar — de ahí que se entregue por dependencia.

from collections.abc import Generator

from sqlalchemy import create_engine

from sqlalchemy.orm import DeclarativeBase, Session, sessionmaker

from app.core.configuracion import configuracion

# check_same_thread solo aplica a SQLite: permite usar la conexión

# desde los hilos en los que FastAPI ejecuta los endpoints síncronos.

opciones_conexion = (

 {"check_same_thread": False}

 if configuracion.url_base_datos.startswith("sqlite")

 else {}

)

motor = create_engine(

 configuracion.url_base_datos,

 connect_args=opciones_conexion,

 echo=configuracion.depuracion, # imprime el SQL generado en desarrollo

 pool_pre_ping=True, # descarta conexiones caídas antes de usarlas

)

FabricaDeSesiones = sessionmaker(

 bind=motor,

 autoflush=False,

 expire_on_commit=False,

)

class Base(DeclarativeBase):

 """Base declarativa: reúne los metadatos de todas las tablas."""

def obtener_sesion() -> Generator[Session, None, None]:

 """Dependencia con ciclo de vida: abre la sesión, la entrega y la cierra."""

 sesion = FabricaDeSesiones()

 try:

 yield sesion

 finally:

 sesion.close()

app/models/biblioteca.py — nuevo archivo

from datetime import date

from sqlalchemy import Boolean, Date, ForeignKey, Integer, String, UniqueConstraint

from sqlalchemy.orm import Mapped, mapped_column, relationship

from app.core.base_datos import Base

class Categoria(Base):

 __tablename__ = "categorias"

 id: Mapped[int] = mapped_column(primary_key=True)

 nombre: Mapped[str] = mapped_column(String(60), unique=True, index=True)

 libros: Mapped[list["Libro"]] = relationship(

 back_populates="categoria", cascade="save-update"

 )

class Autor(Base):

 __tablename__ = "autores"

 id: Mapped[int] = mapped_column(primary_key=True)

 nombre: Mapped[str] = mapped_column(String(120), unique=True, index=True)

 nacionalidad: Mapped[str] = mapped_column(String(60))

 libros: Mapped[list["Libro"]] = relationship(back_populates="autor")

class Libro(Base):

 __tablename__ = "libros"

 id: Mapped[int] = mapped_column(primary_key=True)

 titulo: Mapped[str] = mapped_column(String(200), index=True)

 isbn: Mapped[str] = mapped_column(String(13), unique=True, index=True)

 anio_publicacion: Mapped[int] = mapped_column(Integer)

 ejemplares_totales: Mapped[int] = mapped_column(Integer, default=1)

 ejemplares_disponibles: Mapped[int] = mapped_column(Integer, default=1)

 autor_id: Mapped[int] = mapped_column(ForeignKey("autores.id"))

 categoria_id: Mapped[int] = mapped_column(ForeignKey("categorias.id"))

 autor: Mapped["Autor"] = relationship(back_populates="libros", lazy="joined")

 categoria: Mapped["Categoria"] = relationship(

 back_populates="libros", lazy="joined"

 )

 prestamos: Mapped[list["Prestamo"]] = relationship(back_populates="libro")

class Socio(Base):

 __tablename__ = "socios"

 id: Mapped[int] = mapped_column(primary_key=True)

 documento: Mapped[str] = mapped_column(String(20), unique=True, index=True)

 nombre: Mapped[str] = mapped_column(String(120))

 email: Mapped[str] = mapped_column(String(120), unique=True)

 activo: Mapped[bool] = mapped_column(Boolean, default=True)

 rol: Mapped[str] = mapped_column(String(20), default="socio")

 # Nunca sale en un esquema de respuesta: es un campo del modelo, no del contrato

 contrasena_hash: Mapped[str] = mapped_column(String(255))

 prestamos: Mapped[list["Prestamo"]] = relationship(back_populates="socio")

class Prestamo(Base):

 __tablename__ = "prestamos"

 __table_args__ = (

 # Un mismo socio no puede tener dos préstamos activos del mismo libro

 UniqueConstraint(

 "socio_id", "libro_id", "fecha_prestamo", name="uq_prestamo_unico"

 ),

 )

 id: Mapped[int] = mapped_column(primary_key=True)

 libro_id: Mapped[int] = mapped_column(ForeignKey("libros.id"), index=True)

 socio_id: Mapped[int] = mapped_column(ForeignKey("socios.id"), index=True)

 fecha_prestamo: Mapped[date] = mapped_column(Date)

 fecha_devolucion_esperada: Mapped[date] = mapped_column(Date)

 fecha_devolucion_real: Mapped[date | None] = mapped_column(Date, nullable=True)

 libro: Mapped["Libro"] = relationship(back_populates="prestamos", lazy="joined")

 socio: Mapped["Socio"] = relationship(back_populates="prestamos")

app/main.py — creación de las tablas al arrancar

from contextlib import asynccontextmanager

from fastapi import FastAPI

from app.core.base_datos import Base, motor

from app.models import biblioteca # noqa: F401 — registra los modelos en Base

@asynccontextmanager

async def ciclo_de_vida(app: FastAPI):

 """Se ejecuta una vez al arrancar y una vez al apagar la aplicación."""

 logger.info("Creando las tablas si no existen…")

 Base.metadata.create_all(bind=motor)

 yield

 logger.info("Cerrando el motor de base de datos…")

 motor.dispose()

app = FastAPI(

 title=configuracion.nombre_app,

 version="0.8.0",

 lifespan=ciclo_de_vida,

 # … el resto de los argumentos se mantiene

)

4. Ejemplo detallado: explicación línea por línea

N°

Elemento

Explicación

1

create_engine(url)

Crea el pool de conexiones. Es costoso: se hace una sola vez por proceso, nunca dentro de un endpoint.

2

check_same_thread: False

Exclusivo de SQLite. Sin él, la conexión solo puede usarse desde el hilo que la creó y los endpoints síncronos fallan.

3

echo=configuracion.depuracion

Imprime en consola el SQL que SQLAlchemy genera. Es la mejor herramienta para entender qué hace el ORM; se apaga en producción.

4

pool_pre_ping=True

Verifica que la conexión sigue viva antes de entregarla. Evita el fallo típico tras un periodo de inactividad contra PostgreSQL.

5

expire_on_commit=False

Sin esto, los objetos quedan caducados tras el commit y leer un atributo dispara una consulta nueva — que falla si la sesión ya se cerró.

6

class Base(DeclarativeBase)

Base tipada de SQLAlchemy 2.0. Sustituye a declarative_base() de la versión 1.x.

7

Mapped[int] = mapped_column(...)

El tipo de Python determina el tipo de columna; mapped_column añade las restricciones. Mapped[int | None] equivale a nullable=True.

8

unique=True, index=True

Restricción e índice a nivel de base de datos. Es la última línea de defensa: protege incluso si la validación de la aplicación falla.

9

relationship(back_populates=…)

Declara los dos extremos de la relación. Modificar uno mantiene el otro coherente en memoria.

10

lazy="joined"

Trae el autor y la categoría en la misma consulta que el libro. Sin esto, listar 50 libros dispara 101 consultas: el problema N+1.

11

__table_args__ con UniqueConstraint

Restricciones sobre varias columnas. Van en la tupla de la clase, no en una columna concreta.

12

obtener_sesion con yield

Dependencia con ciclo de vida: lo anterior al yield ocurre antes del endpoint, lo del finally al terminar, incluso si hubo excepción.

13

lifespan=ciclo_de_vida

Sustituye a los eventos startup y shutdown, obsoletos. Lo anterior al yield corre al arrancar; lo posterior, al apagar.

14

create_all(bind=motor)

Crea las tablas que faltan. Sirve para desarrollo; no modifica tablas existentes. Para eso está Alembic, fuera del alcance del curso.

15

sesion.flush()

Envía los INSERT y obtiene los id generados sin cerrar la transacción. Es lo que permite referenciar autores[...].id antes del commit.

5. Errores comunes y cómo evitarlos

Crear el engine dentro de un endpoint: abre un pool nuevo en cada petición y agota las conexiones de la base en minutos.

Olvidar importar el módulo de modelos antes de create_all: las clases nunca se registran en Base.metadata y no se crea ninguna tabla, sin ningún mensaje de error.

Compartir una única Session global entre peticiones: los cambios de un usuario se mezclan con los de otro y la sesión queda inservible tras el primer error.

No cerrar la sesión: las conexiones no vuelven al pool y la aplicación se bloquea al agotarlo. El bloque finally del yield lo garantiza.

Usar declarative_base(), Column() o query.get(): sintaxis de SQLAlchemy 1.x. En 2.0 son DeclarativeBase, mapped_column() y session.get().

Dejar la relación en carga perezosa y recorrerla en un listado: aparece el problema N+1, invisible en desarrollo con cuatro libros y letal con cuatro mil.

Confiar solo en la validación de Pydantic para la unicidad del ISBN: sin unique=True en la columna, dos peticiones simultáneas pueden insertar el duplicado.

Versionar el archivo biblioapi.db: es un artefacto local; va en .gitignore junto al .env.
