Tema de la sesión

Manejo de errores y excepciones en FastAPI

1. Objetivo de la sesión

Al finalizar esta sesión, el aprendiz será capaz de definir excepciones propias del dominio, traducirlas a respuestas HTTP mediante manejadores registrados en la aplicación, y entregar a los clientes un formato de error único y predecible en toda la API.

2. Tres capas de error y quién responde por cada una

Los endpoints escritos hasta ahora repiten el mismo bloque: comprobar si el recurso existe y lanzar HTTPException con un mensaje construido a mano. Funciona, pero el mensaje cambia de forma en cada endpoint y la regla de negocio queda mezclada con el protocolo HTTP.

Capa

Quién la detecta

Respuesta

Formato de los datos

Pydantic, automáticamente

422 con la lista de campos y restricciones incumplidas. No requiere código.

Regla de negocio

El módulo crud o de servicio

Excepción propia del dominio, sin ninguna referencia a HTTP.

Traducción a HTTP

Un manejador registrado en la aplicación

Convierte la excepción del dominio en el código y el cuerpo adecuados.

Fallo imprevisto

El servidor

500 con un mensaje genérico. Nunca se expone la traza al cliente.

Idea clave

El módulo crud no debe saber que existe HTTP. Si mañana la misma lógica se usa desde una tarea programada o desde la línea de comandos, un HTTPException ahí dentro no tendría ningún sentido. La regla de negocio lanza su propia excepción; la traducción a un código de estado ocurre en un único lugar.

Equivalencia con Django REST Framework

DRF tenía APIException y sus subclases (NotFound, ValidationError, PermissionDenied), más un exception_handler global configurable en EXCEPTION_HANDLER. FastAPI ofrece la misma idea con otras piezas: HTTPException para el caso directo y @app.exception_handler(TipoDeExcepcion) para registrar un manejador por tipo. La diferencia práctica es que en DRF el formato de error venía dado por el framework, mientras que aquí lo define el equipo — lo cual obliga a decidirlo explícitamente y a documentarlo.

app/errores.py — nuevo archivo

"""Excepciones del dominio. No conocen HTTP: solo describen qué salió mal."""

class ErrorDeDominio(Exception):

 """Raíz de todas las excepciones de negocio de BiblioAPI."""

 codigo = "error_de_dominio"

 def __init__(self, mensaje: str):

 self.mensaje = mensaje

 super().__init__(mensaje)

class RecursoNoEncontrado(ErrorDeDominio):

 """El identificador solicitado no corresponde a ningún recurso."""

 codigo = "recurso_no_encontrado"

 def __init__(self, recurso: str, identificador: int | str):

 self.recurso = recurso

 self.identificador = identificador

 super().__init__(f"No existe {recurso} con identificador {identificador}.")

class ConflictoDeNegocio(ErrorDeDominio):

 """Los datos son válidos, pero el estado del sistema impide la operación."""

 codigo = "conflicto_de_negocio"

class LimiteDePrestamosSuperado(ConflictoDeNegocio):

 codigo = "limite_de_prestamos_superado"

 def __init__(self, socio_id: int, limite: int = 3):

 super().__init__(

 f"El socio {socio_id} ya tiene {limite} préstamos activos, "

 f"que es el máximo permitido."

 )

class SinEjemplaresDisponibles(ConflictoDeNegocio):

 codigo = "sin_ejemplares_disponibles"

 def __init__(self, libro_id: int):

 super().__init__(f"El libro {libro_id} no tiene ejemplares disponibles.")

app/main.py — registro de los manejadores

import logging

from fastapi import FastAPI, Request, status

from fastapi.exceptions import RequestValidationError

from fastapi.responses import JSONResponse

from app.errores import ConflictoDeNegocio, ErrorDeDominio, RecursoNoEncontrado

from app.routers import autores, libros, socios

logger = logging.getLogger("biblioapi")

# … definición de app y de los include_router (sin cambios)

def _respuesta_error(peticion: Request, estado: int, codigo: str, mensaje: str,

 detalles: list[dict] | None = None) -> JSONResponse:

 return JSONResponse(

 status_code=estado,

 content={

 "codigo": codigo,

 "mensaje": mensaje,

 "ruta": peticion.url.path,

 "detalles": detalles,

 },

 )

@app.exception_handler(RecursoNoEncontrado)

def manejar_no_encontrado(peticion: Request, exc: RecursoNoEncontrado):

 return _respuesta_error(

 peticion, status.HTTP_404_NOT_FOUND, exc.codigo, exc.mensaje

 )

@app.exception_handler(ConflictoDeNegocio)

def manejar_conflicto(peticion: Request, exc: ConflictoDeNegocio):

 return _respuesta_error(

 peticion, status.HTTP_409_CONFLICT, exc.codigo, exc.mensaje

 )

@app.exception_handler(ErrorDeDominio)

def manejar_error_de_dominio(peticion: Request, exc: ErrorDeDominio):

 """Red de seguridad para las subclases que no tengan manejador propio."""

 return _respuesta_error(

 peticion, status.HTTP_400_BAD_REQUEST, exc.codigo, exc.mensaje

 )

@app.exception_handler(RequestValidationError)

def manejar_validacion(peticion: Request, exc: RequestValidationError):

 """Reescribe el 422 de Pydantic con el formato de error de la API."""

 detalles = [

 {

 "campo": ".".join(str(p) for p in error["loc"][1:]),

 "problema": error["msg"],

 }

 for error in exc.errors()

 ]

 return _respuesta_error(

 peticion,

 status.HTTP_422_UNPROCESSABLE_ENTITY,

 "datos_invalidos",

 "Los datos enviados no cumplen el formato esperado.",

 detalles,

 )

@app.exception_handler(Exception)

def manejar_error_inesperado(peticion: Request, exc: Exception):

 """Último recurso: se registra el detalle y se responde algo genérico."""

 logger.exception("Error no controlado en %s", peticion.url.path)

 return _respuesta_error(

 peticion,

 status.HTTP_500_INTERNAL_SERVER_ERROR,

 "error_interno",

 "Ocurrió un error inesperado. Intente de nuevo más tarde.",

 )

 libro = obtener(libro_id)

def prestar_ejemplar(libro_id: int) -> dict:

 """Descuenta un ejemplar disponible; falla si no queda ninguno."""

 libro = obtener_o_fallar(libro_id)

 if libro["ejemplares_disponibles"] <= 0:

 raise SinEjemplaresDisponibles(libro_id)

 libro["ejemplares_disponibles"] -= 1

 return libro

4. Ejemplo detallado: explicación línea por línea

N°

Elemento

Explicación

1

class ErrorDeDominio(Exception)

Raíz común de la jerarquía. Permite capturar cualquier error de negocio con un solo manejador de respaldo.

2

codigo = "recurso_no_encontrado"

Identificador estable, pensado para que el cliente lo compare por igualdad. El mensaje puede reescribirse o traducirse; el código no cambia.

3

@app.exception_handler(RecursoNoEncontrado)

Registra la función como traductora de ese tipo de excepción. Se aplica a toda la aplicación, incluidos los routers.

4

Orden de los manejadores

FastAPI busca el manejador del tipo más específico. Al ser subclases, RecursoNoEncontrado y ConflictoDeNegocio se atienden antes que ErrorDeDominio.

5

peticion.url.path

Incluir la ruta en la respuesta ahorra tiempo de diagnóstico cuando el error llega en un reporte de soporte.

6

JSONResponse(status_code=…, content=…)

Los manejadores devuelven una respuesta construida a mano: aquí ya no aplica response_model, porque no se pasa por el sistema de rutas.

7

RequestValidationError

La excepción que FastAPI lanza cuando falla la validación de Pydantic. Registrar un manejador propio unifica el 422 con el resto de errores de la API.

8

error["loc"][1:]

loc es una tupla como ("body", "isbn"). Se descarta el primer elemento, que indica el origen, para quedarse con el nombre del campo.

9

@app.exception_handler(Exception)

Captura cualquier fallo no previsto. Sin él, un error de programación devuelve la traza completa cuando el servidor corre en modo depuración.

10

logger.exception(...)

Registra la traza en el servidor mientras el cliente solo ve un mensaje genérico. La información de diagnóstico no debe salir en la respuesta.

11

responses={404: {"model": DetalleDeError}}

Publica en /docs no solo el código de error, sino la forma exacta del cuerpo que el cliente recibirá.

5. Errores comunes y cómo evitarlos

Lanzar HTTPException desde el módulo crud: acopla la lógica de negocio al protocolo HTTP y deja esa función inservible fuera de una petición web.

Registrar el manejador de la clase base antes que el de la subclase esperando que el más específico tenga prioridad: FastAPI resuelve por tipo, no por orden, pero un manejador demasiado genérico registrado para Exception puede tapar errores durante el desarrollo.

Devolver la traza o el str(exc) de un error inesperado: expone rutas del sistema de archivos, nombres de variables y a veces credenciales.

Usar 500 para errores de negocio previsibles. Un socio sin cupo de préstamos es 409; un 500 le dice al cliente que la culpa es del servidor.

Cambiar el formato del error sin actualizar responses en los decoradores: la documentación queda describiendo un cuerpo que la API ya no devuelve.

Capturar Exception dentro del endpoint con un try/except genérico: se pierden los manejadores globales y cada endpoint termina inventando su propio formato.
