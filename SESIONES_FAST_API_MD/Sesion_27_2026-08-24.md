Tema de la sesión

Documentación automática (Swagger/OpenAPI)

1. Objetivo de la sesión

Al finalizar esta sesión, el aprendiz será capaz de personalizar la documentación OpenAPI que FastAPI genera —metadatos de la aplicación, etiquetas, resúmenes, descripciones, ejemplos y respuestas de error documentadas— y habrá reorganizado el proyecto en routers, primera de las dos refactorizaciones planeadas del bloque.

2. Qué es OpenAPI y de dónde sale /docs

FastAPI construye, en cada arranque, un documento JSON que describe la API completa siguiendo el estándar OpenAPI 3.1: rutas, verbos, parámetros, esquemas de entrada y salida, y códigos de respuesta. Ese documento está disponible en /openapi.json y es lo que consumen las dos interfaces visuales.

Elemento

Función

/openapi.json

El contrato de la API en formato legible por máquinas. Es la fuente; todo lo demás se deriva de él.

/docs (Swagger UI)

Interfaz interactiva: permite ejecutar peticiones reales desde el navegador. Es la herramienta de trabajo durante el desarrollo.

/redoc (ReDoc)

Documentación de lectura, sin ejecución. Más adecuada para entregar a un equipo de frontend o a un cliente.

tags

Agrupan endpoints por recurso en la interfaz. Sin ellos, todos aparecen en un bloque «default» indistinto.

summary y description

Título corto y explicación larga de cada endpoint. Si no se indican, se usan el nombre de la función y su docstring.

responses

Documenta los códigos de error posibles. FastAPI solo conoce por sí solo el caso de éxito y el 422.

Idea clave

La documentación no es un archivo que se escribe aparte y se desactualiza: es una proyección del código. Si un endpoint aparece mal documentado, la corrección se hace en la firma de la función o en su esquema, nunca en un documento paralelo.

Equivalencia con Django REST Framework

En DRF instalaron drf-spectacular, lo añadieron a INSTALLED_APPS, configuraron SPECTACULAR_SETTINGS, registraron las rutas del esquema y decoraron las vistas con @extend_schema para afinar el resultado. En FastAPI ese paquete no existe porque no hace falta: el esquema se genera desde los tipos declarados y la personalización se hace con argumentos del propio decorador de ruta. La contrapartida es que documentar los errores sí requiere trabajo explícito, mientras que @extend_schema los recogía de la vista.

3. Refactorización 1: de un archivo único a routers

Esta refactorización es un evento didáctico planeado, no una corrección de errores. main.py ha crecido hasta mezclar la configuración de la aplicación con los endpoints de dos recursos. APIRouter permite dividirlo por recurso, y de paso es lo que hace útiles a los tags.

from typing import Annotated

from fastapi import APIRouter, HTTPException, Path, Query, Response, status

from app.crud import libros as crud_libros

from app.schemas.libro import LibroActualizar, LibroCrear, LibroRespuesta

router = APIRouter(

 prefix="/libros",

 tags=["Libros"],

 responses={

 404: {"description": "El libro solicitado no existe."},

 },

)

@router.get(

 "",

 response_model=list[LibroRespuesta],

 summary="Listar el catálogo",

 description=(

 "Devuelve los libros del catálogo. Admite filtro por categoría, "

 "por disponibilidad y paginación mediante límite y desplazamiento."

 ),

)

def listar_libros(

 categoria: Annotated[

 str | None, Query(description="Categoría exacta.", examples=["novela"])

 ] = None,

 solo_disponibles: Annotated[bool, Query()] = False,

 limite: Annotated[int, Query(ge=1, le=50)] = 10,

 desplazamiento: Annotated[int, Query(ge=0)] = 0,

):

 resultado = crud_libros.listar()

 if categoria is not None:

 resultado = [l for l in resultado if l["categoria"] == categoria]

 if solo_disponibles:

 resultado = [l for l in resultado if l["ejemplares_disponibles"] > 0]

 return resultado[desplazamiento : desplazamiento + limite]

@router.get(

 "/{libro_id}",

 response_model=LibroRespuesta,

 summary="Consultar un libro",

)

def obtener_libro(libro_id: Annotated[int, Path(ge=1)]):

 libro = crud_libros.obtener(libro_id)

 if libro is None:

 raise HTTPException(

 status_code=status.HTTP_404_NOT_FOUND,

 detail=f"No existe un libro con id {libro_id}.",

 )

 return libro

@router.post(

 "",

 response_model=LibroRespuesta,

 status_code=status.HTTP_201_CREATED,

 summary="Registrar un libro",

 responses={

 201: {"description": "Libro registrado correctamente."},

 409: {"description": "Ya existe un libro con ese ISBN."},

 },

)

def crear_libro(datos: LibroCrear):

 if crud_libros.existe_isbn(datos.isbn):

 raise HTTPException(

 status_code=status.HTTP_409_CONFLICT,

 detail=f"Ya existe un libro registrado con el ISBN {datos.isbn}.",

 )

 return crud_libros.crear(datos.model_dump())

@router.put(

 "/{libro_id}",

 response_model=LibroRespuesta,

 summary="Reemplazar un libro",

 responses={409: {"description": "El ISBN pertenece a otro libro."}},

)

def reemplazar_libro(libro_id: Annotated[int, Path(ge=1)], datos: LibroCrear):

 if crud_libros.existe_isbn(datos.isbn, excluir_id=libro_id):

 raise HTTPException(

 status_code=status.HTTP_409_CONFLICT,

 detail=f"El ISBN {datos.isbn} pertenece a otro libro.",

 )

 libro = crud_libros.reemplazar(libro_id, datos.model_dump())

 if libro is None:

 raise HTTPException(

 status_code=status.HTTP_404_NOT_FOUND,

 detail=f"No existe un libro con id {libro_id}.",

 )

 return libro

@router.patch(

 "/{libro_id}",

 response_model=LibroRespuesta,

 summary="Actualizar parcialmente un libro",

)

def actualizar_libro(libro_id: Annotated[int, Path(ge=1)], datos: LibroActualizar):

 libro = crud_libros.actualizar(libro_id, datos.model_dump(exclude_unset=True))

 if libro is None:

 raise HTTPException(

 status_code=status.HTTP_404_NOT_FOUND,

 detail=f"No existe un libro con id {libro_id}.",

 )

 return libro

@router.delete(

 "/{libro_id}",

 status_code=status.HTTP_204_NO_CONTENT,

 summary="Eliminar un libro",

 responses={409: {"description": "El libro tiene ejemplares prestados."}},

)

def eliminar_libro(libro_id: Annotated[int, Path(ge=1)]):

 if crud_libros.obtener(libro_id) is None:

 raise HTTPException(

 status_code=status.HTTP_404_NOT_FOUND,

 detail=f"No existe un libro con id {libro_id}.",

 )

 if crud_libros.tiene_prestamos_activos(libro_id):

 raise HTTPException(

 status_code=status.HTTP_409_CONFLICT,

 detail="No se puede eliminar un libro con ejemplares prestados.",

 )

 crud_libros.eliminar(libro_id)

 return Response(status_code=status.HTTP_204_NO_CONTENT)

from app.datos import SOCIOS, buscar_socio_por_id

@router.get("", summary="Listar socios")

def listar_socios(

 activo: Annotated[bool | None, Query()] = None,

 rol: Annotated[str | None, Query()] = None,

 resultado = SOCIOS

 if activo is not None:

 if rol is not None:

4. Ejemplo detallado: explicación línea por línea

N°

Elemento

Explicación

1

APIRouter(prefix="/libros")

Todas las rutas del módulo cuelgan de ese prefijo. Dentro del router las rutas se escriben relativas: "" y "/{libro_id}".

2

tags=["Libros"] en el router

Se aplica a todos sus endpoints. Definir la etiqueta una vez evita repetirla en cada decorador.

3

responses={404: {...}} en el router

Documenta un error común a todos los endpoints del recurso, sin repetirlo endpoint por endpoint.

4

summary="Listar el catálogo"

Texto que aparece a la derecha de la ruta en /docs. Sin él se muestra el nombre de la función, poco legible para quien consume la API.

5

description=(…)

Explicación larga. Sustituye al docstring cuando este describe detalles internos que no interesan al consumidor.

6

Query(examples=["novela"])

Precarga un valor de ejemplo en el formulario de Swagger UI: quien prueba la API no tiene que inventarse datos.

7

responses={409: {...}}

FastAPI documenta el éxito y el 422, pero no conoce los errores que se lanzan con HTTPException dentro de la función. Hay que declararlos.

8

openapi_tags=TAGS

Da descripción y orden a las secciones de la documentación. Sin esta lista, las etiquetas aparecen sin explicación y en orden de aparición.

9

app.include_router(libros.router)

Monta el router en la aplicación. Es la única línea de main.py que sabe de la existencia del recurso.

10

json_schema_extra={"examples": …}

Ejemplo del cuerpo de la petición. En Pydantic v2 va dentro de model_config; la clave schema_extra de la versión 1 ya no se reconoce.

11

tags=["Sistema"] en @app.get

Los endpoints que quedan en main.py también se etiquetan, para que no aparezcan sueltos en un grupo «default».

5. Errores comunes y cómo evitarlos

Repetir el prefijo dentro del router: escribir @router.get("/libros") con prefix="/libros" produce la ruta /libros/libros, que responde 404 en la ruta esperada.

Olvidar app.include_router: el módulo se importa sin error, pero ningún endpoint queda registrado y todas las rutas devuelven 404.

Terminar el prefijo con barra (prefix="/libros/"): FastAPI lanza «Prefix cannot end with '/'» al arrancar.

Dar por documentado un error solo porque se lanza con HTTPException. Si no está en responses, no aparece en /docs ni en /openapi.json.

Usar class Config con schema_extra: es sintaxis de Pydantic v1 y en v2 se ignora silenciosamente, así que el ejemplo simplemente no aparece.

Dejar todos los endpoints sin tags: la documentación se vuelve una lista plana e inservible en cuanto hay más de diez rutas.
