Tema de la sesión

Path params y query params con Pydantic

1. Objetivo de la sesión

Al finalizar esta sesión, el aprendiz será capaz de recibir datos por la ruta y por la cadena de consulta, aplicando restricciones de validación con Path() y Query() mediante Annotated, y de entender qué hace FastAPI cuando el dato recibido no cumple el tipo o el rango declarado.

2. Dos formas de recibir datos en una petición GET

Una petición GET no lleva cuerpo. Todo lo que el cliente quiere comunicar viaja en la URL, y hay exactamente dos lugares donde puede hacerlo. La decisión de cuál usar no es estética: cambia el significado del endpoint.

Tipo

Ejemplo

Cuándo se usa

Path parameter

/libros/7

Identifica el recurso. Es obligatorio: sin él la ruta no existe. Si el valor no corresponde a ningún recurso, la respuesta es 404.

Query parameter

/libros?categoria=novela&limite=10

Modifica cómo se devuelve una colección: filtra, ordena, pagina. Es opcional por naturaleza; si se omite, se aplica un valor por defecto.

Idea clave

Si al quitar el dato la ruta deja de tener sentido, es un path param. Si al quitarlo la ruta sigue funcionando y solo cambia el resultado, es un query param. Por eso /libros/novela está mal diseñado: filtrar por categoría no identifica un libro.

Annotated: la forma actual de declarar restricciones

Python permite adjuntar metadatos a una anotación de tipo mediante Annotated[tipo, metadato]. FastAPI lo aprovecha para separar el tipo del dato de las reglas que debe cumplir. Es la sintaxis recomendada desde FastAPI 0.95 y la única que usaremos en el curso.

Restricción

Significado

ge=1 / le=100

Mayor o igual que / menor o igual que. Para números.

gt=0 / lt=2100

Estrictamente mayor / menor que.

min_length=3 / max_length=80

Longitud mínima y máxima de una cadena.

pattern=r"^\d{13}$"

Expresión regular que la cadena debe cumplir.

description="…"

Texto que aparece en /docs junto al parámetro.

default=None

Valor cuando el cliente no envía el parámetro; lo hace opcional.

Equivalencia con Django REST Framework

En DRF los path params llegaban como self.kwargs["pk"] —siempre cadenas, con la conversión y la validación a cargo de ustedes— y los query params como request.query_params.get("categoria"), sin tipado ni valores por defecto declarados. FastAPI invierte la responsabilidad: se declara lo que se espera y el framework rechaza lo que no encaje antes de entrar en la función. El equivalente conceptual de un filtro de django-filter aquí es, sencillamente, un parámetro tipado más en la firma.

@app.get("/libros")

def listar_libros(

 categoria: Annotated[

 str | None,

 Query(description="Filtra por categoría exacta: novela, memorias, tecnica."),

 ] = None,

 anio_min: Annotated[

 int | None,

 Query(ge=1450, le=2100, description="Año de publicación mínimo."),

 ] = None,

 buscar: Annotated[

 str | None,

 Query(min_length=3, max_length=80, description="Texto contenido en el título."),

 ] = None,

 solo_disponibles: Annotated[

 bool,

 Query(description="Si es verdadero, oculta los libros sin ejemplares libres."),

 ] = False,

 limite: Annotated[int, Query(ge=1, le=50)] = 10,

 desplazamiento: Annotated[int, Query(ge=0)] = 0,

):

 """Lista el catálogo aplicando filtros opcionales y paginación."""

 resultado = LIBROS

 if categoria is not None:

 resultado = [l for l in resultado if l["categoria"] == categoria]

 if anio_min is not None:

 resultado = [l for l in resultado if l["anio_publicacion"] >= anio_min]

 if buscar is not None:

 resultado = [l for l in resultado if buscar.lower() in l["titulo"].lower()]

 if solo_disponibles:

 resultado = [l for l in resultado if l["ejemplares_disponibles"] > 0]

 return {

 "total": len(resultado),

 "limite": limite,

 "desplazamiento": desplazamiento,

 "resultados": resultado[desplazamiento : desplazamiento + limite],

 }

4. Ejemplo detallado: explicación línea por línea

N°

Elemento

Explicación

1

from typing import Annotated

Importa el mecanismo que permite adjuntar metadatos a un tipo. Es parte de la biblioteca estándar desde Python 3.9.

2

Annotated[str | None, Query(...)]

El tipo dice qué se espera (una cadena o nada); Query dice cómo validarlo y documentarlo. Son dos responsabilidades separadas en una sola declaración.

3

= None al final del parámetro

Es lo que hace opcional al query param. Sin valor por defecto, FastAPI lo trata como obligatorio y responde 422 si falta.

4

Query(ge=1450, le=2100)

Rango permitido para el año. Si llega 1200, FastAPI responde 422 con el detalle del campo y la restricción incumplida, sin ejecutar la función.

5

Query(min_length=3)

Evita búsquedas de una sola letra que devolverían casi todo el catálogo. La validación es del framework, no del código de negocio.

6

solo_disponibles: bool = False

FastAPI convierte las cadenas true, True, 1, yes y on en verdadero. No hay que parsear nada a mano.

7

limite / desplazamiento

Paginación manual. En la sesión del 27 de agosto esta pareja se convertirá en una dependencia reutilizable con Depends.

8

Path(ge=1, ...)

Los path params también se validan. Un id de cero o negativo se rechaza con 422 antes de tocar los datos.

9

raise HTTPException(404, ...)

La ausencia del recurso es un error de negocio, no una excepción de Python. Se comunica con el código de estado adecuado.

10

Orden de las rutas

/libros se declara antes que /libros/{libro_id}. FastAPI evalúa las rutas en orden de declaración y una ruta con parámetro puede capturar lo que iba destinado a una ruta fija.

5. Errores comunes y cómo evitarlos

Declarar el parámetro sin valor por defecto y esperar que sea opcional: FastAPI responde «Field required» con código 422 en cuanto se omite.

Poner un parámetro con valor por defecto antes de uno sin valor por defecto: Python lanza «SyntaxError: non-default argument follows default argument» al importar el módulo.

Declarar /libros/{libro_id} antes que /libros/disponibles: la ruta con parámetro captura la palabra «disponibles» e intenta convertirla a entero, devolviendo 422 en lugar de la ruta esperada.

Usar el estilo antiguo libro_id: int = Path(...). Sigue funcionando, pero mezcla tipo y validación en la asignación; el estándar actual es Annotated.

Filtrar por categoría en la ruta (/libros/novela) en lugar de la cadena de consulta: mezcla identificación con filtrado y obliga a una ruta nueva por cada filtro futuro.
