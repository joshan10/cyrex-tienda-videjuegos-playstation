2. Mapa de conceptos repasados

Lo que debe quedar claro

25

Modelos de datos con Pydantic

Un esquema por operación: Crear, Actualizar y Respuesta. field_validator valida un campo; model_validator valida el modelo completo. exclude_unset distingue «no enviado» de «enviado en null».

26

Métodos HTTP y códigos de estado

POST crea y responde 201; PUT reemplaza; PATCH modifica lo enviado; DELETE responde 204 sin cuerpo. 422 es formato, 409 es estado del sistema. response_model controla la salida.

27

Documentación automática

La documentación se deriva del código. APIRouter divide por recurso; tags, summary y responses la hacen legible. Los errores lanzados a mano hay que declararlos.

Idea clave

Las tres sesiones construyen la misma frontera desde ángulos distintos: el esquema define qué entra y qué sale, el código de estado define cómo terminó la operación, y la documentación publica ambas cosas. Un endpoint bien hecho no necesita que nadie explique cómo se usa.

Preguntas de diagnóstico

N°

Pregunta

Respuesta esperada

1

¿Por qué no basta un único esquema para crear, actualizar y responder?

Porque los campos obligatorios cambian en cada caso. Un esquema único obliga a hacer todo opcional y la validación deja de proteger.

2

Un PATCH envía {"titulo": null}. ¿Qué debe ocurrir?

exclude_unset lo incluye porque fue enviado. Si el campo no admite nulos, el esquema debe rechazarlo con 422; enviarlo no es lo mismo que omitirlo.

3

¿Qué diferencia hay entre @field_validator y @model_validator?

El primero valida un campo aislado; el segundo se ejecuta después y puede comparar varios campos entre sí.

4

Se registra un libro con ISBN de 13 dígitos que ya existe. ¿422 o 409?

409. El formato es correcto; lo que impide la operación es el estado del catálogo.

5

¿Por qué DELETE no devuelve cuerpo?

Porque se declara con 204 No Content, y ese código significa por definición que no hay cuerpo en la respuesta.

6

¿Para qué sirve response_model si la función ya devuelve el diccionario correcto?

Filtra y valida la salida. Impide que un campo interno se escape a la respuesta aunque esté en el diccionario.

7

Un endpoint lanza HTTPException(409) pero /docs no lo muestra. ¿Por qué?

Porque FastAPI no inspecciona el cuerpo de la función. El código debe declararse en responses del decorador.

8

¿Qué hace prefix en APIRouter y qué error produce repetirlo?

Antepone la ruta base a todos los endpoints del router. Repetirlo en el decorador genera rutas duplicadas del tipo /libros/libros.

class AutorBase(BaseModel):

 nombre: str = Field(min_length=3, max_length=120)

 nacionalidad: str = Field(min_length=3, max_length=60)

 @field_validator("nombre", "nacionalidad")

 @classmethod

 def normalizar(cls, valor: str) -> str:

 return " ".join(valor.split()).title()

from itertools import count

from app.datos import LIBROS

AUTORES: list[dict] = [

 {"id": 1, "nombre": "Gabriel García Márquez", "nacionalidad": "Colombiana"},

 {"id": 2, "nombre": "José Eustasio Rivera", "nacionalidad": "Colombiana"},

 {"id": 3, "nombre": "Héctor Abad Faciolince", "nacionalidad": "Colombiana"},

]

_siguiente_id = count(4)

def _con_conteo(autor: dict) -> dict:

 """Añade cuántos libros del catálogo pertenecen a ese autor."""

 return {

 **autor,

 "libros_registrados": sum(1 for l in LIBROS if l["autor"] == autor["nombre"]),

 }

def listar() -> list[dict]:

 return [_con_conteo(autor) for autor in AUTORES]

def obtener(autor_id: int) -> dict | None:

 for autor in AUTORES:

 if autor["id"] == autor_id:

 return _con_conteo(autor)

 return None

def existe_nombre(nombre: str, excluir_id: int | None = None) -> bool:

 return any(

 autor["nombre"].lower() == nombre.lower() and autor["id"] != excluir_id

 for autor in AUTORES

 )

def crear(datos: dict) -> dict:

 autor = {"id": next(_siguiente_id), **datos}

 AUTORES.append(autor)

 return _con_conteo(autor)

def actualizar(autor_id: int, cambios: dict) -> dict | None:

 for autor in AUTORES:

 if autor["id"] == autor_id:

 autor.update(cambios)

 return _con_conteo(autor)

 return None

def eliminar(autor_id: int) -> bool:

 for autor in AUTORES:

 if autor["id"] == autor_id:

 AUTORES.remove(autor)

 return True

 return False

app/routers/autores.py — nuevo archivo

from typing import Annotated

from fastapi import APIRouter, HTTPException, Path, Response, status

from app.crud import autores as crud_autores

from app.schemas.autor import AutorActualizar, AutorCrear, AutorRespuesta

router = APIRouter(

 prefix="/autores",

 tags=["Autores"],

 responses={404: {"description": "El autor solicitado no existe."}},

)

@router.get("", response_model=list[AutorRespuesta], summary="Listar autores")

def listar_autores():

 return crud_autores.listar()

@router.get("/{autor_id}", response_model=AutorRespuesta, summary="Consultar un autor")

def obtener_autor(autor_id: Annotated[int, Path(ge=1)]):

 autor = crud_autores.obtener(autor_id)

 if autor is None:

 raise HTTPException(

 status_code=status.HTTP_404_NOT_FOUND,

 detail=f"No existe un autor con id {autor_id}.",

 )

 return autor

@router.post(

 "",

 response_model=AutorRespuesta,

 status_code=status.HTTP_201_CREATED,

 summary="Registrar un autor",

 responses={409: {"description": "Ya existe un autor con ese nombre."}},

)

def crear_autor(datos: AutorCrear):

 if crud_autores.existe_nombre(datos.nombre):

 raise HTTPException(

 status_code=status.HTTP_409_CONFLICT,

 detail=f"Ya existe un autor llamado {datos.nombre}.",

 )

 return crud_autores.crear(datos.model_dump())

@router.patch(

 "/{autor_id}",

 response_model=AutorRespuesta,

 summary="Actualizar parcialmente un autor",

)

def actualizar_autor(autor_id: Annotated[int, Path(ge=1)], datos: AutorActualizar):

 cambios = datos.model_dump(exclude_unset=True)

 if not cambios:

 raise HTTPException(

 status_code=status.HTTP_422_UNPROCESSABLE_ENTITY,

 detail="Debe enviarse al menos un campo para actualizar.",

 )

 autor = crud_autores.actualizar(autor_id, cambios)

 if autor is None:

 raise HTTPException(

 status_code=status.HTTP_404_NOT_FOUND,

 detail=f"No existe un autor con id {autor_id}.",

 )

 return autor

@router.delete(

 "/{autor_id}",

 status_code=status.HTTP_204_NO_CONTENT,

 summary="Eliminar un autor",

 responses={409: {"description": "El autor tiene libros en el catálogo."}},

)

def eliminar_autor(autor_id: Annotated[int, Path(ge=1)]):

 autor = crud_autores.obtener(autor_id)

 if autor is None:

 raise HTTPException(

 status_code=status.HTTP_404_NOT_FOUND,

 detail=f"No existe un autor con id {autor_id}.",

 )

 if autor["libros_registrados"] > 0:

 raise HTTPException(

 status_code=status.HTTP_409_CONFLICT,

 detail=(

 f"El autor tiene {autor['libros_registrados']} libro(s) en el "

 "catálogo; no puede eliminarse."

 ),

 )

 crud_autores.eliminar(autor_id)

 return Response(status_code=status.HTTP_204_NO_CONTENT)

4. Errores comunes recopilados de las sesiones anteriores

Usar @validator o class Config: sintaxis de Pydantic v1. En v2 son @field_validator y model_config = ConfigDict(...).

Olvidar @classmethod bajo @field_validator, con el consiguiente PydanticUserError al importar el módulo.

Devolver el diccionario interno sin response_model y filtrar campos que no debían salir.

Omitir status_code=201 en el POST o devolver cuerpo en un DELETE declarado con 204.

Repetir el prefijo del router dentro del decorador y generar rutas /recurso/recurso.

Lanzar HTTPException sin declarar el código en responses: el error existe pero no está documentado.

Escribir la lógica de datos dentro del endpoint en lugar del módulo crud, lo que obligará a reescribirla al llegar SQLAlchemy.
